# Integration Testing

Integration testing focuses on how different parts of your application work together. While unit tests isolate a single function or class, integration tests verify that your code interacts correctly with external dependencies like databases or other APIs.

## Specific Things to Learn

- [ ] Understand the difference between unit and integration tests.
- [ ] Set up a test environment for integration testing.
- [ ] Write tests that interact with a real database.
- [ ] Implement mocking for external third-party APIs.
- [ ] Manage test data setup and teardown.

## Lesson

### 1. Introduction to Integration Testing

#### 1.1 Terminology

To ensure clarity throughout this lesson, we will use the following terms:

- **Your Project**: The Node.js code you are currently developing.
- **API / API Testing**: Your project's interface that exposes features via HTTP. Testing this involves ensuring requests are handled correctly and return the expected responses.
- **Backend / Service**: Any external API or service your project calls via HTTP (e.g., the GitHub API).
- **Database**: A specific backend used by your project for persistent data storage and retrieval.

Integration testing ensures that "Your Project" communicates correctly with these "Backends" and "Databases."
